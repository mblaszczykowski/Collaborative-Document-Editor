# Review repair status

This maps every finding in [the application review](app-review.md) to the current implementation. The reported confidentiality, synchronization, persistence, undo, and delivery defects received repairs. Several broader product, accessibility, scale, and operational proposals remain incomplete; this document does **not** claim that every proposed improvement has shipped.

**Fixed** means the specific reported failure has an implementation repair, with evidence cited below. It does not mean every related workflow has been independently verified. **Partially addressed** means useful changes shipped but part of the finding remains. **Remaining enhancement** means the proposed capability or engineering work is still outstanding. Test-file references identify regression evidence, not a claim that every suggested acceptance scenario is present.

## Validation

The focused security run passed **101 tests with zero failures or errors** before the final combined validation. It covered account/document retry-key isolation, payload conflicts, permission invalidation, expiry, failed authorization lookups, invitation races, durable replica ownership, existing permission/comment/access workflows, and management-port authorization.

Final combined validation on 2026-10-14:

| Check | Result |
| --- | --- |
| Maven `clean verify` with the Colima socket override | Passed: 1,504 application tests, including two configured skips, and 101 CRDT tests; zero failures/errors. Includes the populated V13→V14 comment migration regression. |
| Frontend production build, unit tests, lint | Passed: 204 tests across 19 files; TypeScript/build and oxlint clean. |
| Full Playwright run against built Docker images | All 29 passed with `E2E_APP_URL=http://localhost:15173 E2E_API_URL=http://localhost:19090 E2E_PRODUCTION=true npx playwright test`. Includes both recorded demos, first-visit offline reload, retained unsent edits, direct-link restore, 100,000-character redo, reply refresh, sharing and mobile layout. |
| npm audit | Zero reported vulnerabilities after dependency updates. |
| Docker build and proxy | Both images built. Nginx configuration validated; browser scenarios used its real API/WebSocket proxy. Backend container healthcheck passed. |
| Frontend healthcheck | Container validation exposed IPv6 `localhost` connection refusal. Switched the probe to `127.0.0.1` and verified its exact command succeeds in the rebuilt image. This healthcheck-only change followed the passing browser run; application assets were unchanged. |
| Documentation and presentation | README files and all four diagram sources/SVGs updated; both GIFs regenerated from successful current demo recordings. Script syntax, relative links and whitespace checked. Historic performance measurements are explicitly labeled. |

Independent reviewers found and corrected repair regressions including post-commit HTTP errors, conflicting operation claims, stale rename/index writes, generated delete bounds, WebSocket subscription ordering, stale draft completion after remount, and cache/ACK ordering during immediate offline reload. No further confirmed regression remains in the reviewed paths. Tests and source review do not establish every possible execution path. Real provider sign-in, physical-device IME behavior, a complete screen-reader audit, whole-installation upgrades and sustained capacity measurements require separate evidence.
